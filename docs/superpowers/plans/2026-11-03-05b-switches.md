# Turning Cards On and Off Implementation Plan (plan 5b)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app changes Community: one switch per card, Remove, the sync dialog instead of 5a's silent following, links to moved add-ons repaired without asking, refusal of every change while MSFS runs, and a banner line for Packages that are on but Not shown.

**Architecture:** Core gets a sim refusal that comes before any state change (`SimRunningException`), a snapshot update for choices that need no link change, the card switch's position, and the new banner item. `AppServices` composes the existing write path (`ChangeApplier`, `SyncCoordinator`, `PackageRemover`); `AppSession` calls it under its lock, runs `SyncCoordinator.Start` at every discovery instead of `CommunityFollower.Follow`, and classifies Community read under the lock for every board and sync check. Two new view models (card dialog, sync dialog) and two overlays show it.

**Tech Stack:** C# / .NET 10 (`net10.0-windows`), WPF, WPF-UI 4.x, CommunityToolkit.Mvvm 8.x, xUnit, `System.Reflection.Metadata` (existing).

**Spec:** `docs/superpowers/specs/2026-11-03-plan-5b-switches-design.md` (approved 2026-11-03), which deviates from `docs/superpowers/specs/2026-10-25-mvp-design.md` as its Deviations section lists. Review history and the implementation findings this plan covers: issue #22, comment 6615995123 ("Carried to the plan"). Background: `ANALYS.md` "Beslut för plan 5b (2026-11-03)". Executors read the spec and this plan.

**Models (Rickard's rule):** implementers Sonnet (Haiku for Tasks 2 and 9); per-task review Opus (Sonnet for Tasks 2 and 9); final whole-branch review Opus 5.5 or newer.

## Decisions (my calls — Rickard confirms at plan approval)

- **D1 Refusal form.** A change while the sim runs throws `SimRunningException` (Core, `Linking`), whose message is the spec's copy "Close MSFS to change add-ons". `ChangeApplier.EnsureSimClosed()` is the first statement of `SetChoices`, `Relink`, `ApplyLinks`, `SetActiveCopy` and `RemoveBrokenLink`, before `BeginChange` and before the E5 loop, so a refusal changes nothing in memory or on disk. `SyncCoordinator.Resolve` calls it before `Reconciler.Resolve`; `PackageRemover.Remove` throws the same exception as its first statement, before `BeginChange` and the Removable check, so a locked file with MSFS running shows the sim text. The `Defer` path is deleted. `ApplyResult.Deferred` and `DeferredEmpty` stay only as `FlushPending`'s "the sim runs, nothing flushed" result, which `SyncCoordinator.Start` uses for leftovers from older data.
- **D2 No-op choices update the snapshot.** `ChangeApplier.Apply` updates the snapshot entries of the changed Packages *and* of `plan.NoOp`, so a card switch decides its Packages' waiting rows also when it needs no link change (spec, Deviations). When no rows wait, the entry already equals Community, so nothing changes.
- **D2b A copy gone before the click is refused, never linked.** The index a click plans with comes from the last discovery and can still list a deleted copy, and `JunctionFileSystem.CreateJunction` doesn't check its target. `ILinkFileSystem` gains `bool DirectoryExists(string path)` (`JunctionFileSystem`: `Directory.Exists`); before any link op, `ChangeApplier.Apply` moves every Create or Repoint whose `TargetPath` doesn't exist to the rejections as the new `RejectReason.TargetGone`, and stores nothing for it. It is a refused change (spec: "the copy gone since the dialog opened"), so no message: the row shows the board's reason once the next discovery has seen the folder go.
- **D3 Community is read under the lock.** `ScanService` reads Community on its own thread, outside the session lock, so a run's `discovery.Community` can predate an own change. Every board the session builds, every `Settlement.Apply` and every sync check classifies Community read under the lock (`CommunityClassifier.Classify(services.ReadCommunity(), index)`), never the run's copy. About 150 entries: cheap, and it needs no own-change counter.
- **D4 The board for `Start` and `Resolve`** is always built from the current input (the discovery input with the cached contents at a discovery, the completed input at a completion) with Community from D3. It is never empty, also when the wall is not shown yet (first run, D3 of 5a).
- **D5 Session API.** `IAppSession` gains `IsSimRunning`, `SwitchCardAsync(CardRef)`, `RemoveAsync(CardRef, PackageKey)` and `ResolveSyncAsync(IReadOnlyDictionary<PackageName, SyncChoice>)`. Each returns the message to show, or `null` on success, and moves to the thread pool like `RescanAsync`. `SessionView` gains `SyncPrompt? Sync` and `bool SyncHeldBack`.
- **D6 Sync rows at a discovery.** With rows: when a sync dialog is open, its rows are replaced (it stays open, also when the sim runs); otherwise, while the sim runs, `SyncHeldBack` is set and no dialog opens; otherwise the dialog opens. With no rows, both clear. `ResolveSyncAsync` resolves the rows of the latest discovery held by the session. **During the first run's scan** (phase Scanning, the wall not shown yet, 5a D3) the sync dialog shows above the scanning screen, like in any phase from Scanning on; after Resolve a board is published only when a wall is already shown, and the phase is never changed, so "Scanning…" stays until the run completes.
- **D7 Copy I decided (the spec leaves it to the builder).** Sync row texts: LinkAppeared "Linked outside the app", LinkDisappeared "Link removed outside the app", LinkRetargeted "Link now points to `<NewTarget>`", Moved (only for a Package that is off, D10) "Off in the app, but linked; moved to `<NewTarget>`", OnButNotLinked "On in the app, but not linked", OffButLinked "Off in the app, but linked". Group titles: the card's name (provisional cards included, so first-run rows group under their provisional cards); "Not shown"; "No card yet" for a row whose Package is on no card and not in the Not shown list (for example a name only the snapshot knows). Buttons: "Keep Community for all", "Restore app state for all", "Apply". Card dialog: "Remove", "Close".
- **D10 Links to moved add-ons are repaired** (spec item 4b, Rickard 2026-11-06). In `SyncCoordinator.Start`, after `Adopt` (first run) or `Diff`: every Package whose stored choice is on and whose entry is Stale is re-pointed through `applier.ApplyLinks` with `DesiredLink(true, <active copy>)` (the copy `Reconciler.MovedRow` picks today), and gets no row. While the sim runs nothing is repaired and `StartupOutcome.RepairsWaiting` is true. `RegisterLibrary` does the same for the Packages it adopts. A Package that is off with a Stale entry still gets a `Moved` row, but its meaning turns around: `DefaultChoice` is `KeepCommunity`, and in `Reconciler.Resolve` `KeepCommunity` gives `DesiredLink(true, NewTarget)` (on, re-pointed) and `RestoreApp` gives `DesiredLink(false)` (the broken link removed). Its labels are the ordinary "Keep Community" / "Restore app state".
- **D8 The confirmation for Remove** is a WPF `MessageBox` (Yes/No) injected into the card dialog as `Func<string, bool>`, so tests answer it.
- **D9 Dev-check tools** live in `tools/dev-check/` outside the solution: `New-TestPackages.ps1` (writes a Packages root with `Community` and `Official\Steam`, and a Library with three Packages, two of them linked) and the stand-in console project `FlightSimulator/FlightSimulator.csproj` (`AssemblyName` FlightSimulator, waits on `Console.ReadLine`).

## Review Focus

1. **A click while a scan is mid-run** (between its discovery and its completion): the completed board still shows the change, and no sync row appears for it (Task 5, `A_switch_during_a_run_survives_its_completion`).
2. **MSFS starts after the dialog opened:** the click is refused with "Close MSFS to change add-ons", nothing is saved, and the switch stays disabled until the dialog is reopened (Task 1, `Every_change_is_refused_while_the_sim_runs_and_nothing_changes`; Task 6, `A_click_refused_by_the_sim_keeps_the_switch_disabled`).
3. **`userdata.db` locked by the CLI or an SQLite editor at the click:** the dialog shows the file's message and no link is touched (Task 5, `A_locked_database_refuses_the_switch_before_any_link`).
4. **A Package's copy deleted between building the board and the click:** the click is rejected without a crash and, after the refresh, the row shows the board's own reason (Task 5, `A_copy_gone_before_the_click_shows_the_board_reason`).
5. **Another tool changes Community while the sync dialog is open:** the rows are replaced and the user's choices are kept for rows with the same Package and reason (Task 7, `New_rows_keep_the_choices_of_rows_still_listed`).
