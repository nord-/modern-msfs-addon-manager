# Link Engine Implementation Plan (plan 1 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested, headless engine that finds the MSFS 2020 install, discovers Packages in Libraries, classifies Community, stores the user's on/off choices, reconciles against Community, applies link changes safely (deferred while the sim runs), and proposes Libraries on first run — plus a read-only `status` command to check it against the real machine.

**Architecture:** Pure domain rules in `AddonManager.Core` (no file system, no WPF), operating on records produced by `AddonManager.Infrastructure` (junctions, Community and Library reading, JSON storage) and `AddonManager.Sim2020` (install location, sim process). Core defines the interfaces (`ILinkFileSystem`, `ICommunitySource`, `IUserStateStore`, `ISimProcessMonitor`, `IFolderTree`); tests use fakes for Core and temporary folders for Infrastructure.

**Tech Stack:** C# / .NET 10 SDK, `.slnx` solution, xUnit (built-in `dotnet new xunit` template), System.Text.Json, P/Invoke for junctions, GitHub Actions on `windows-latest`.

**Spec:** `docs/superpowers/specs/2026-10-25-mvp-design.md` (sections 5, 6.1–6.3, 6.8, 7.1, 7.4, 11, 12, 13). Vocabulary: `GLOSSARY.md`.

## Global Constraints

- .NET 10 (`net10.0`, Windows-specific projects `net10.0-windows`); nothing that blocks a move to .NET 11.
- Windows only. Junctions, never symlinks, are created; no admin rights required.
- Removing a link must remove only the link (non-recursive `Directory.Delete(path, false)` on a reparse point); never delete through a link; never delete a real folder.
- Never move, modify or delete user files. Sim-managed packages, Fixed entries and Managed elsewhere Packages are never changed.
- Package names, container names and Airport codes are compared case-insensitively (`StringComparer.OrdinalIgnoreCase`).
- MSFS 2020 loads Packages only from `Official\<store>` and Community; folders in the Packages root are not Packages.
- MIT license; no code copied or translated from Dave's GSX Profile Manager (GPL-3.0).
- CRLF line endings (`.gitattributes` already declares `* text=auto eol=crlf`).
- Commit messages carry no AI attribution (user's global rule).
- User data lives in `%APPDATA%\ModernMsfsAddonManager\userdata.json`; the scan cache will live in `%LOCALAPPDATA%\ModernMsfsAddonManager\` (plan 2).

## Review Focus

1. **A Library on an unplugged drive:** discovery must report it unreachable, keep all user data, and never offer to remove its links as Broken. Plan decision: a link whose target lies under an unreachable Library is classified **Offline** (not Broken) and is ignored by reconciliation and planning (rule E3). Tests in Tasks 6, 7, 9 and 10B.
2. **Malformed or odd `manifest.json`** (invalid JSON, UTF-8 BOM, missing `title`): the Package is still discovered and displayed by folder name. Test in Task 6.
3. **Non-ASCII and long paths** in junction targets (real: `C:\Sim\Orbx Library\msfs\EPGD Gdańsk Lech Wałęsa Airport\…`): create, read and remove must round-trip. Test in Task 3.
4. **Case differences** between a Community entry name, its target path and the Package folder name (`Asobo_C172SP_AS1000` vs `Asobo_C172sp_AS1000`): treated as the same. Tests in Task 7 and Task 10A.
5. **App closed while the sim runs with pending changes:** the pending set survives and is applied exactly once on the next start when the sim isn't running. Tests in Task 10B and Task 15.

## Engine rules

These rules apply across Tasks 4–15. Each task restates the ones it implements.

- **E1 Name and target must agree.** A link is Managed (or Stale) only when its entry name equals the Package name (case-insensitive). A link whose target is a Library Package under another name (for example `zzz-x` → `x`) is External. The planner acts only on an entry with the Package's own name.
- **E2 The active copy is stored.** `PackageState.ActiveCopyPath` is set by `Adopt` (to the copy Community points to), after every successful Create or Repoint, by KeepCommunity on a LinkRetargeted row, and by `SetActiveCopy`. `ActiveCopySelector` precedence: stored path → Community target → Library order, then path.
- **E3 Offline is left alone.** Entries classified Offline, and Packages whose active copy lies under an unreachable Library, produce no sync rows, no self-check rows and no link operations. They stay in `Pending` until their Library is back.
- **E4 Choices that need no operation are stored at once** (Off with no entry, Off when the name is held by a non-Managed entry, On when already linked to the active copy).
- **E5 A rejected turn-on is never stored as On.** In `SetChoices` the choice isn't stored; in `Relink`/`FlushPending` a NameTaken sets the stored choice Off; every rejection is reported.
- **E6 Target existence and normalisation.** `TargetExists` = `Directory.Exists(normalisedTarget)` on the target path, never on the link (every API reports a dangling junction itself as existing). Normalisation maps `\??\UNC\server\…` to `\\server\…` and keeps `\\?\Volume{…}\…` paths as they are. A link whose target isn't an absolute drive or UNC path after normalisation is External, never Broken.
- **E7 Snapshot entries are re-classified on use.** A snapshot entry counts as Managed for `Diff` when its name is an indexed Package and its target is a copy of that Package or no longer exists.
- **E8 An apply updates only the snapshot entries it touched.** The whole snapshot is replaced only by `Adopt` and `AcceptSnapshot`, so foreign changes made in between are still found by the next `Diff`.
- **E9 A failed Repoint is rolled back.** If creating the new link fails after the old one was removed, the old link is recreated and the failure reported.
- **E10 Locked active copies can't be switched.** `SetActiveCopy` on a locked Package is rejected as Locked; the user removes the lock first.
- **E11 No nested Libraries.** `LibraryProposer` drops a proposal that lies inside another; `PackageIndex` ignores a second copy with the same path.

The startup sequence (spec 7.2 and 12; this is the state machine plan 5 drives):
1. Read and classify Community.
2. **First run** (`Snapshot == null`): `Adopt`, `AcceptSnapshot`, return `FirstRun = true`, no rows.
3. Otherwise `FollowLocked`, then `Diff`. If there are no rows, `AcceptSnapshot` (records silent External/Fixed/locked changes) and save.
4. `FlushPending` (only Packages not in a row; a Package in a row waits for the user's decision).
5. Return the rows for the sync dialog.

`Resolve`: `Reconciler.Resolve` (returns the link changes; Moved rows are stored only by the apply path), then `ApplyLinks`, then `AcceptSnapshot` for the resolved Packages only (failed ones keep their old entry and come back as rows) and for the whole Community once no row is left — also when the relink was deferred because the sim started meanwhile, so KeepCommunity rows don't come back. `OnSimExited`: `FlushPending`. Plan 5 wires `OnSimExited` to the sim process ending and calls `Start` at launch.
